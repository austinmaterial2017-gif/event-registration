# 每个活动独立 Google Sheet 设计

## 目标

管理员只填写活动资料并按一次“创建活动”。系统自动为该活动建立一张新的私人 Google Sheet、初始化所需栏目并完成连接。以后创建其他活动时重复相同的简单操作，不需要填写 Sheet ID、修改 Apps Script 或重新部署。

所有活动继续显示在同一个 GitHub Pages 报名网站。参加者、座位、电子票、二维码、取消、换座和签到会自动使用该活动所属的数据表。

## 已确认的选择

- 每次新建活动时自动建立一张独立 Google Sheet。
- 同一个活动内的多个场次、讲师、座位、问题、报名和签到共用该活动的 Sheet。
- 不采用人工建立 Sheet 后粘贴 ID 的日常流程。
- 不为每个活动复制一套 Apps Script。
- 当前私人 Sheet 保留为永久总目录，不公开分享。
- 管理员顶部“活动、场次、座位、问题、记录、签到”等导航必须可以点击并滚动到对应区域。

## 数据结构

### 永久总目录

现有注册表 Sheet 继续作为系统唯一的永久根。新增两个私人工作表：

1. `活动目录`
   - 保存 `eventId`、活动 Sheet ID、活动 Sheet 名称、状态和公开活动摘要。
   - Sheet ID 只会出现在受保护的 Apps Script 和私人总目录中。
   - GitHub Pages、电子票和公开 API 不返回 Sheet ID。

2. `票券索引`
   - 保存票券 token 的 SHA-256 摘要、`eventId`、`registrationId` 和活动路由，用来把电子票、取消、换座和签到请求送到正确的活动 Sheet。
   - 不保存可直接使用的票券 token。
   - 不保存参加者姓名、电话、电邮或报名答案。

`系统设置`、管理员策略和安全切换状态仍留在永久总目录。

### 每个活动的独立 Sheet

新建活动时，公开后端以部署者身份创建私人 Google Sheet，名称使用安全处理后的活动名称与短活动编号。系统自动建立并验证：

- `活动`
- `场次`
- `座位`
- `报名问题`
- `参加者`
- `报名项目`
- `签到记录`
- `操作记录`

活动 Sheet 只保存一个活动及其相关资料，不再要求管理员输入或复制 Sheet ID。

## 创建活动流程

1. 管理员在受保护页面填写活动名称、日期和规则。
2. 管理员按“创建活动”。
3. 后端先产生活动编号，再建立和初始化独立 Sheet。
4. 后端把活动资料写进独立 Sheet。
5. 后端最后把活动与 Sheet 的映射发布到永久总目录。
6. 管理员页面显示“活动已创建”，并提供受保护的“打开活动数据表”按钮。
7. 公开网站从总目录读取可公开活动，并在同一个首页显示。

只有第 5 步完成后，活动才算创建成功。建立或初始化失败时，不会发布半完成活动；已经存在的活动继续正常使用。

## 编辑和管理员体验

- 管理员先选择一个活动，再管理该活动的场次、座位、报名问题、报名记录和签到。
- 页面自动带入活动编号，不再要求用户手工复制 `eventId`。
- “活动、场次、座位、问题、记录、签到”等顶部导航使用页面内滚动，不受 Apps Script iframe 或 `<base target="_top">` 影响。
- 原本的“整套系统切换数据表”功能改为高级维护区并默认折叠，避免误用。
- 旧活动归档后，其独立 Sheet 和所有历史资料保留，不删除。

## 参加者与工作人员流程

- 活动列表只读取永久总目录中的安全公开摘要，不暴露任何 Sheet ID。
- 参加者选择活动后，后端以 `eventId` 找到对应的活动 Sheet。
- 报名成功时，系统在活动 Sheet 写入完整报名资料，并在永久总目录写入最小票券路由索引。
- 电子票查询、取消、换座、公开验票和工作人员签到通过票券索引定位活动 Sheet。
- 二维码继续只包含网站验证网址和不透明票券 token，不包含 Sheet ID 或参加者资料。

## 一致性与失败处理

- 所有活动映射和票券路由写入继续受脚本锁保护。
- 新建活动使用“先准备、后发布”顺序；失败时不会让公开网站看到未完成活动。
- 报名必须先在活动 Sheet 完整提交，再发布票券路由；索引发布失败时记录完整性警报并进行可恢复处理。
- 编辑活动时，先更新活动 Sheet，再更新总目录的公开摘要；任一步失败都返回固定中文错误，不返回内部异常或 Sheet ID。
- 找不到活动映射、映射格式错误或目标 Sheet 无法读取时安全拒绝操作，不尝试写入其他活动。
- 多个活动可以同时开放报名，切换或归档一个活动不会暂停其他活动。

## 权限和部署

- 两个 Apps Script 项目仍然保留：匿名公开后端，以及需要 Google 登录的工作人员／管理员项目。
- 只需要本次更新源码并重新部署两个项目一次。
- 因为系统需要自动建立私人 Sheet，并把建立者加入编辑权限，更新后第一次运行可能要求一次新的 Google 权限确认。
- 之后建立活动不需要再次修改脚本属性、复制代码或部署。
- 新活动 Sheet 由公开后端部署者拥有并保持私人；创建活动的管理员获得编辑权限，受保护管理员页面可以显示该活动的“打开数据表”按钮。
- 公开目录继续禁止出现 Sheet ID、管理员网址、允许名单和共享密钥。

## 兼容与迁移

- 现有永久总目录和管理员设置原样保留。
- 当前没有已开放活动，因此首次升级不需要迁移参加者资料。
- 如果升级时检测到旧业务 Sheet 内已有活动，系统不会自动拆分或删除；它们进入只读兼容状态，并要求管理员另行确认迁移。
- 新功能启用后创建的活动一律使用独立 Sheet。

## 测试与完成标准

- 创建两个活动会产生两个不同的私人 Sheet。
- 两个活动同时出现在同一个公开报名首页。
- 每个活动的场次、问题、座位、报名和签到只写入自己的 Sheet。
- 电子票、取消、换座、验票和签到能从 token 定位正确的活动 Sheet。
- 任何公开响应和 GitHub Pages 文件都不包含 Sheet ID 或私人配置。
- 活动 Sheet 建立、初始化或目录发布失败时，不出现公开的半成品活动。
- 管理员顶部导航在 Apps Script 页面内可点击并滚动。
- 原有安全、报名、座位、票券和签到测试继续通过。
- 更新后的两个 Apps Script 部署与 GitHub Pages 经过实际端到端检查。
