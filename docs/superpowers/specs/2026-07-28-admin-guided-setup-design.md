# 管理员活动设置引导设计

## 目标

管理员建立或编辑活动时，界面必须一直说明“目前正在设置哪个活动”，并根据活动选项自动带到下一项需要填写的内容。新活动在管理员最终确认前只作为草稿保存，不建立独立活动 Sheet。管理员不需要自己猜应该按“场次、座位、问题”中的哪一个，也不会因为误按保存而产生多个活动 Sheet。

## 核心体验

### 1. 清楚区分新活动与现有活动

- 按“新建活动”后，固定提示条显示“正在建立新活动草稿（尚未生成数据表）”。
- 选择已有活动后，固定提示条显示“正在设置：活动名称”及活动状态。
- 场次、座位、问题、记录和签到区域都沿用同一个活动提示，不允许看起来像在编辑另一个活动。

### 2. 根据选择决定下一步

草稿保存成功后，系统检查活动设置并自动跳到第一个仍需要设置的项目：

1. 场次选择规则不是“无需选择”时，先跳到“场次”。
2. 座位模式不是“自由入座／无座位”时，在场次完成后跳到“座位”。
3. 如果还没有报名问题，跳到“问题”。
4. 所有必需项目都有内容后，停在活动摘要，并显示“基本设置已完成”。

没有启用的功能会略过，不要求管理员填写无关项目。

### 3. 人工确认后才生成活动数据表

- 活动、场次、座位规则和报名问题先储存在永久管理表的私人草稿区。
- 草稿不会显示给参加者，也不会建立新的活动专用 Sheet。
- 所有必需项目完成后显示“确认建立活动并生成数据表”按钮。
- 按钮点击后先显示确认摘要；管理员再次确认才执行。
- 系统一次性建立该活动的私人 Google Sheet，并把草稿中的活动、场次、座位和问题完整写入。
- 生成成功后显示“数据表建立成功”和“打开数据表”按钮。
- 生成失败时保留完整草稿，不发布活动，也不留下可见的半成品活动。
- 已生成的活动继续直接保存到自己的活动 Sheet，不再回到草稿区。
- “生成数据表”和“开放报名”是两个独立动作；生成数据表不会自动开放报名。
- 未生成的草稿可以在二次确认后直接删除，不会留下活动 Sheet。
- 已生成且完全没有报名、票券或签到记录的活动，可以在二次确认后从目录移除，并把活动 Sheet 移到 Google Drive 回收站。
- 已经存在报名、票券或签到历史的活动不能永久删除，只能结束或归档，以保留完整记录。

### 4. 相关设置才显示

- 选择不需要场次时，活动表单隐藏最少／最多场次数量，并说明参加者不需要选讲座场次。
- 选择需要场次时，显示场次数量规则，并提示保存后建立讲师、日期、时间和地点。
- 选择自由入座／无座位时，隐藏座位区域输入。
- 选择需要选座时，显示座位区域输入，并提示保存后开放或生成座位。
- 报名问题仍由管理员一个一个建立，但参加者会在同一份报名表一次填写全部可见问题。

### 5. 每次操作都有明确反馈

- 按下保存后，按钮立即显示“正在保存…”并暂时禁止重复点击。
- 成功后显示具体结果，例如“场次保存成功”或“座位已开放”。
- 失败时保留已填内容，并说明是哪一项没有保存。
- 自动跳转前显示一句短提示，例如“活动已保存，下一步请建立场次”。

## 数据与安全

草稿只存放在永久管理表的私人草稿区，不会进入公开活动目录。生成后，每个活动仍使用自己的私人 Google Sheet；参加者只看到已经生成且当前开放的活动。Apps Script 的部署和连接保持不变，管理员不需要为每个活动重新粘贴代码或设置权限。

正式生成后，原有功能保持不变：多场次和讲师、选部分或全部场次、选座或自由入座、自定义报名问题、倒数、电子票、二维码、分场次签到、取消报名、换座、结束和归档。

## 测试

- 新活动与现有活动的提示必须不同。
- 普通草稿保存不能建立新的活动 Sheet。
- 最终确认只能建立一个活动 Sheet，重复点击必须被阻止并返回同一结果。
- 生成过程任何一步失败时，草稿必须保留，公开目录不得出现该活动。
- 生成成功后活动仍保持非公开，直到管理员另外执行“开放报名”。
- 草稿删除不得影响其他草稿、活动目录或活动 Sheet。
- 已生成活动的删除必须先验证报名、票券和签到记录全部为空；否则返回明确说明并保持所有资料不变。
- 不同场次和座位组合必须跳到正确的下一步。
- 没启用的设置必须略过。
- 现有活动切换后，所有表单必须带上正确活动 ID。
- 自动跳转不能造成第二次保存或重复建立资料。
- 参加者的选场次、选座、填表、提交、票券及二维码流程必须继续通过原有测试。
