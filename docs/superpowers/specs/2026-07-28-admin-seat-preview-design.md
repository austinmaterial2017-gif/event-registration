# 管理员座位即时预览设计

日期：2026-07-28

## 目标

管理员填写座位模式、前方名称、区域、行数和每行座位时，立即看到接近参与者报名页面的座位图，减少保存后才发现布局错误的情况。

## 采用方案

采用内嵌即时预览（方案 A）：

- 桌面版把预览放在座位设置右侧。
- 手机版把预览放在设置下方。
- 提供“放大预览”按钮，在同一页面显示较大的预览层。
- 预览沿用参与者页面的座位视觉语言：前方名称、区域标题、座位编号、可选择、暂选中、已被选择。
- 管理员可在预览里点一个座位模拟“暂选中”，但不会写入 Google Sheet、锁位或占用真实座位。

## 数据与行为

预览只读取当前画面上的内容：

- 活动表单：座位图前方名称。
- 座位表单：模式、区域名称、行数、每行座位。
- 当前活动已经存在的座位：用于显示参与者真实会看到的可用与不可用状态。

输入或选择改变时，预览即时重绘。`none` 模式显示“自由入座，无需选座”；数字无效或资料不足时，预览明确指出还需要填写什么，不发送后台请求。

## 其他栏位反馈

同一次更新会统一管理员表单的反馈：

- 场次：标题、容量、开始与结束时间。
- 座位：模式、区域、行数、每行座位。
- 报名问题：问题文字、选项、排序、JSON。
- 报名记录：报名 ID、新座位 ID。

修改内容后，旧错误提示会改成“内容已修改，请保存确认”；无效资料不会送到后台。

## 错误处理

预览失败不会影响真实座位数据。保存失败时保留管理员已填写的内容，并显示具体栏位原因。所有真实座位状态仍以后台及 Google Sheet 为准。

## 验证

- 自动测试预览的 `none`、`self`、`auto`、`zone` 模式。
- 验证座位编号、区域、前方名称和状态颜色。
- 验证预览点击不会产生后台保存请求。
- 验证桌面与手机布局。
- 回归测试所有管理员保存按钮与参与者报名、选座流程。
