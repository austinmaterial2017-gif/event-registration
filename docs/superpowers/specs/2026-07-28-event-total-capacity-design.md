# 活动总容量设计

## 目标

在保留每个场次独立容量的同时，为每个活动加入一个总参加人数上限。

## 管理员设置

- 活动编辑区新增「活动总容量（0 = 不限人数）」。
- 只接受大于或等于 0 的整数。
- 旧活动没有此字段时按 0 处理，不改变现有行为。

## 容量规则

- 活动总容量限制该活动内有效报名的不同参加者人数。
- 场次容量继续限制每个场次的有效报名人数。
- 新报名必须同时通过活动总容量与所有已选场次容量检查。
- 同一位参加者管理现有报名或追加场次时，不重复占用活动总名额。
- 已取消或非有效状态的报名不占用活动总名额。
- 0 表示不限人数。

## 并发与错误反馈

- 活动总容量检查与报名写入在现有脚本锁内完成，避免多人同时取得最后名额时超额。
- 活动总容量满时返回独立错误码，并向参加者显示「活动总名额已满」。
- 场次满额仍显示现有的场次满额反馈。

## 数据与公开页面

- 总容量保存在活动记录，不新增 Google Sheet。
- 公开活动资料包含安全的总容量数字，但不公开参加者名单或私人资料。
- 管理员页面显示清楚的 0 = 不限人数说明。

## 测试

- 默认值、输入验证与管理员保存。
- 总容量 0 不限制报名。
- 未满时可报名，满额时拒绝新参加者。
- 追加场次不重复计算同一参加者。
- 取消后释放活动总名额。
- 公开资料与管理员界面契约。
- 完整回归测试与公开文件安全检查。
