# 参加者管理报名与追加场次设计

日期：2026-07-28  
状态：已由用户确认

## 目标

让参加者从现有电子票页面管理同一笔报名，追加或取消个别场次，不产生第二张票。修改必须继续遵守活动、场次、容量、时间冲突、座位和签到规则，并在任何失败时保留原本报名。

## 已确认的产品规则

1. 入口放在现有电子票页面，不建立独立管理网址。
2. 参加者使用票号及该活动配置的重复身份验证资料（电话号码或 Email）取得自己的电子票。
3. 在报名截止时间前，参加者可以追加新场次或取消原本选择的个别场次。
4. 报名截止后，管理功能变为只读。
5. 必选场次不能取消；已开始或已签到的场次也不能取消。
6. 修改后沿用原本的票号、二维码、验证资料和电子票，不产生新票。
7. 不提供绕过身份重复判断的第二次追加报名。

## 参加者界面

电子票成功载入且服务端确认可管理时，票面下方显示“管理我的报名”区域：

- 当前已报名场次预先勾选。
- 可追加场次可供选择。
- 已满、已开始、时间冲突、必选或不可取消的场次保留显示，并注明不可操作原因。
- 选择需要场次专属座位的新场次时，出现相应空位选择。
- 活动使用共用座位时，追加或取消场次不会要求重选共用座位。
- 保存前显示将新增和取消的场次摘要。
- 保存期间按钮进入明确的处理中状态，并阻止重复提交。
- 保存成功后显示“报名已更新”，并以服务端返回的新电子票重新绘制页面。
- 保存失败时显示固定、可理解的中文错误，页面恢复服务端确认的原始选择。

## 服务端接口与授权

新增一个公开但需要票主验证的操作：

`updateRegistrationSessions({ ticketNumber, verificationValue, sessionIds, seatChoices, seatHoldOwner })`

接口只接受票号、验证资料、目标场次集合、必要的座位选择和不具身份意义的座位暂存拥有者。服务端必须：

1. 从永久票券索引解析目标活动数据表。
2. 验证票券路由、活动、报名编号及票号完全一致。
3. 使用活动配置的身份字段验证票主，不信任浏览器提交的参加者资料。
4. 在同一脚本锁内读取规则、校验目标状态并执行修改。
5. 返回现有安全电子票投影，不返回原始个人资料、数据表 ID 或内部错误。

## 服务端验证

每次修改均以目标场次全集进行验证，而不是只验证新增项目：

- 活动状态允许报名，且服务端时间未超过报名截止时间。
- 票券及所有报名项目仍为有效状态。
- 目标场次不存在重复或未知 ID。
- 所有必选场次仍在目标集合内。
- 最少和最多场次数量符合活动规则。
- 场次组别选择上限符合配置。
- 目标场次之间没有时间冲突。
- 新增场次尚未开始并仍有容量。
- 已开始或已有签到记录的原场次不能移除。
- 座位模式与目标场次匹配，新增座位仍可用或由本次持有人暂存。
- 共用座位继续属于同一报名；场次专属座位随新增或移除正确占用或释放。

## 原子写入与恢复

修改在一个锁内完成，并先保存受影响记录的快照：

1. 计算新增、保留及移除场次。
2. 计算需要占用、保留及释放的座位。
3. 将报名项目更新为新的目标场次和座位集合。
4. 更新座位拥有者及状态。
5. 保留原票券路由及二维码令牌。
6. 写入不含个人资料的操作记录。

任何中途写入失败都恢复报名项目、座位及操作记录前的状态。恢复失败时返回完整性错误并留下管理员可查的安全告警，不向参加者显示内部细节。

## 数据与签到

- 不新增第二名参加者、不新增第二个票号，也不复制答案。
- 现有报名项目继续使用相同 `registrationId`；如当前资料模型按场次拆行，则在同一报名编号下增减对应记录。
- 签到只接受修改后仍属于报名的场次。
- 旧二维码继续有效，并在扫描后显示最新场次。
- 已有签到历史永久保留，因此相关场次不能由参加者移除。

## 管理员影响

管理员现有报名记录页面继续显示合并后的最新场次和座位。操作记录增加“参加者更新场次”的条目，包含报名编号、增加的场次 ID、移除的场次 ID 和时间，不保存验证资料。

## 错误处理

前端只显示固定错误，例如：

- 已超过报名修改期限
- 必选场次不能取消
- 场次名额已满
- 所选场次时间冲突
- 座位刚刚被其他人选择
- 已开始或已签到的场次不能取消
- 报名资料已变化，请重新载入电子票

未知错误统一显示“暂时无法更新报名，请稍后再试”，不泄露脚本、数据表或堆栈信息。

## 测试范围

自动测试至少覆盖：

1. 无座位活动追加及取消场次。
2. 必选、最少／最多场次和组别上限。
3. 容量满额及并发容量竞争。
4. 时间冲突、已开始场次及已签到场次。
5. 共用座位和场次专属座位的占用与释放。
6. 座位暂存拥有者不符及并发抢位。
7. 报名截止边界由服务端时间决定。
8. 重复点击只产生一次更新。
9. 写入失败后的报名与座位完整恢复。
10. 票号、二维码及票券路由保持不变。
11. 参与者页面保存后重新显示最新电子票。
12. 公共响应和错误不泄露私人资料或数据表标识。

## 非目标

- 不修改原报名问题答案。
- 不允许参加者更改姓名、电话或 Email。
- 不建立新票、新二维码或新报名编号。
- 不允许报名截止后由参加者自行修改。
- 本功能不改变管理员取消整笔报名或调整座位的既有能力。
