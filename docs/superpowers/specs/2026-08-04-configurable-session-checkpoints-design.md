# 可配置场次多次签到设计

## 目标

让管理员为每个场次独立设置签到方式和签到次数。同一张电子票可在同一个场次完成多次签到，每次签到分别使用 Google Apps Script 服务器时间记录，并防止同一次重复签到。

## 管理员设置

每个场次新增以下设置：

- `checkInMode`：场次签到方式。
  - `none`：不需要签到。
  - `single`：签到一次。
  - `automatic`：自动记录下一次尚未完成的签到。
  - `manual`：工作人员手动选择本次签到点。
- `checkInCount`：需要完成的签到次数，`single` 固定为 1，`automatic` 和 `manual` 可设置为 1 至 20。
- `checkInLabels`：每次签到的选填名称，每行一个。空白名称自动显示为“第 N 次签到”。

管理员在场次表单中设置这些字段。草稿场次与已经生成数据表的场次都使用相同规则。旧场次没有这些设置时，保持现有行为，默认视为 `single`。

活动级现有签到方式继续保留，用作总开关：

- 活动设置为“不需要签到”时，所有场次均不可签到。
- 活动允许按场次签到时，读取每个场次自己的签到方式和次数。
- 活动设置为“整个活动只签到一次”时，继续使用现有活动级签到，不读取场次多次签到设置。

## 工作人员操作

工作人员扫描电子票 QR Code 后，系统只显示参加者已经报名的场次。

### 手动选择

场次设置为 `manual` 时，页面列出所有签到点及状态。工作人员选择一个尚未完成的签到点，再按确认：

- 未签到：显示可操作按钮。
- 已签到：显示服务器签到时间和工作人员账号，不允许重复操作。
- 未开放或已截止：显示不可操作原因。

### 自动下一次

场次设置为 `automatic` 时，工作人员选择该场次并按签到。服务器从第 1 次开始，自动记录最早尚未完成的签到点。全部完成后，再次操作会显示“本场次所有签到已完成”。

### 单次和无需签到

- `single` 沿用现有一次签到流程。
- `none` 显示“此场次不需要签到”，不提供确认按钮。

## 数据结构

不新增公开个人资料，也不公开 Google Sheet。

每个签到点使用稳定 ID：`checkpoint-1`、`checkpoint-2`，依次类推。场次策略保存在现有管理员设置的场次政策中：

```json
{
  "checkInMode": "manual",
  "checkInCount": 4,
  "checkInLabels": ["入场", "", "", "离场"]
}
```

签到记录表的完整表头固定为：

```text
checkInId, registrationId, eventId, sessionId, checkpointId,
checkpointLabel, checkedInAt, checkedInBy, status
```

每条记录保留：

- 活动 ID
- 场次 ID
- 报名 ID
- 签到点 ID
- 签到点显示名称
- Google 服务器签到时间
- 当前登录的工作人员账号
- 状态

系统初始化或升级时，在现有 `sessionId` 后插入两列并补齐表头，不删除旧签到记录；原有时间、工作人员和状态单元格整体向右移动并保持原值。旧记录的空白签到点在读取时按 `checkpoint-1` 处理，因此原有“已签到”不会消失，也不会被重复签到。

## 服务器规则

服务器是唯一有权决定签到结果的组件：

1. 验证工作人员 Google 账号在允许名单内。
2. 验证票券有效、报名仍有效，并且参加者确实报名该场次。
3. 验证活动和场次允许签到，以及当前时间在允许范围内。
4. 根据场次策略验证 `checkpointId`，或为自动模式选择下一次。
5. 在同一个脚本锁内检查重复记录并写入签到。
6. 返回最新的全部签到点状态。

参加者手机、工作人员手机或电脑时间不能改变签到结果。

## 错误与反馈

页面每次操作都必须提供明确反馈：

- “正在读取签到状态……”
- “正在记录第 N 次签到……”
- “第 N 次签到成功。”
- “这一次已经完成签到。”
- “本场次所有签到已完成。”
- “此场次不需要签到。”
- “当前不在签到时间内。”

请求处理中禁用相关按钮，防止工作人员连续点击造成重复请求。服务器仍以唯一签到点记录和脚本锁作为最终防重复保护。

## 管理员记录显示

管理员“签到记录”区域增加签到点名称和序号。管理员可以按活动、场次和报名记录查看每一次服务器签到时间，不删除任何历史记录。

## 兼容与隐私

- 旧活动和旧场次默认维持每场次签到一次。
- 旧电子票二维码继续使用，不需要重新发票。
- 参与者只看见自己的电子票，不会看见其他人的签到记录。
- GitHub Pages 不包含工作人员允许名单、Google Sheet ID、共享密钥或参加者资料。
- 所有写入继续通过受保护的工作人员 Apps Script 和统一公开后端完成。

## 测试范围

自动测试必须覆盖：

- 旧场次默认单次签到。
- 每个场次可独立保存 `none`、`single`、`automatic`、`manual`。
- 次数范围和名称数量验证。
- 手动模式只记录指定签到点。
- 自动模式按顺序记录下一次未完成签到点。
- 同一签到点不能重复记录，并发请求也只能成功一次。
- 一个场次的签到不影响另一个场次。
- 未报名场次、无效票、无权限账号、活动关闭和超出签到时间均拒绝写入。
- 旧签到表升级后仍保留旧记录，并映射为第一次签到。
- 管理员与工作人员页面都有进行中、成功和失败反馈。
- 公开报名、选座、电子票、取消、换座和原有签到模式回归测试全部通过。

## 不在本次范围

- 每个签到点独立设置开放和截止时间。
- 参加者自行签到。
- GPS、蓝牙或现场 Wi-Fi 限制。
- 签到后自动发送邮件或 WhatsApp。
