# 报名照片上传设计

日期：2026-08-24

## 目标

在现有报名问题系统中加入两种图片能力：管理员可为任何报名题目附上一张说明图片；“上传照片”题型则让匿名参加者使用手机拍照或从相册选择照片作答。参加者答案照片必须保持私人，且系统不得公开 Drive 文件夹、Google 密码或管理资料。现有活动选择、场次、座位、倒计时、电子票、找回票券和签到行为保持不变。

本阶段只实现照片上传，不同时加入评分、线性量表和网格题型。

## 管理员体验

管理员在“报名问题”的字段类型中选择“上传照片”，并可配置：

- 必填或选填；
- 最多上传数量，默认 3 张；
- 单张最大容量，默认 5 MB；
- 排序、显示或隐藏，沿用现有题目设置。

任何题型都可另外附上一张“题目说明图片”，例如付款 QR、地图、样本照片或题目插图。管理员可上传、预览、更换或移除这张图片。题目图片默认只支持适合网页显示的 JPEG、PNG 和 WebP，单张最大 5 MB；系统会在报名页面压缩显示尺寸，但保留可点开查看大图的能力。

照片问题不能用作姓名、电话、电邮或重复身份判断字段，也不显示在电子票正文。管理员保存时，前后端都会验证数量和大小必须在安全范围内。

## 参加者体验

报名页面先在题目文字下显示管理员附加的说明图片，再为“上传照片”题型显示系统文件选择器。手机可直接拍照或选择相册，桌面可选择本地照片。参加者答案支持 JPEG、PNG、HEIC 和 HEIF。

选择后页面显示：

- 文件名和缩图（浏览器可预览时）；
- 单张大小；
- 删除该照片按钮；
- 已选数量与允许上限；
- 提交时的“正在上传照片”进度状态。

客户端会在送出前拦截错误格式、超出单张大小、超出数量及必填但没有照片的情况。最终核对页显示照片文件名，不把大型照片资料写进页面文字或电子票。

## 储存方式

图片不会写入 GitHub，也不会直接塞进 Google Sheet 单元格。系统分开管理两类图片：

- 题目说明图片属于公开报名内容，储存在专用的题目图片文件夹，并只开放该单一文件的匿名读取；不公开文件夹列表。
- 参加者答案照片储存在私人答案根文件夹；每个活动使用独立子文件夹，每次报名再使用独立子文件夹，文件不开放匿名读取。

两个 Drive 根文件夹 ID 分别存在 Apps Script Script Properties 的 `QUESTION_IMAGE_ROOT_FOLDER_ID` 与 `REGISTRATION_UPLOAD_ROOT_FOLDER_ID`，不会出现在 GitHub 前端。若答案根文件夹未配置，系统拒绝照片题目的提交并返回清楚的管理员配置错误；若题目图片文件夹未配置，管理员不能上传题目图片，但普通题目仍可保存。

文件名由服务器生成安全名称，包含报名编号、问题编号、序号和原扩展名；原始文件名只作为资料显示，不用于 Drive 路径。

## 提交流程与一致性

浏览器先完成现有报名资料验证，再把照片转换为上传载荷，与最终报名请求一起送到 Apps Script。服务器按以下顺序处理：

1. 验证活动开放状态、场次、座位和普通答案；
2. 验证照片题目确实属于该活动，且仍处于显示状态；
3. 检查 MIME 类型、数量、单张大小和总大小；
4. 建立报名资料并生成报名编号；
5. 写入 Drive 照片；
6. 将照片元数据写入该题答案；
7. 完成原有参加者、报名项目、票券索引和座位事务。

照片答案只保存结构化元数据：Drive 文件 ID、原文件名、MIME 类型、字节数和管理员可打开的 Drive 链接。公开 API、电子票与找回票券接口不得返回 Drive 文件 ID 或私人链接给参加者。

公开活动资料只返回题目说明图片的受控显示 URL，不返回其 Drive 文件夹资料；参加者答案照片绝不进入公开活动资料。

若照片写入后报名事务失败，服务器会删除本次已建立的文件和文件夹。若清理也失败，则写入操作记录供管理员处理，但仍不把失败报名当成成功。

## Google Sheet 显示

原始“报名项目”继续保存结构化答案，不改变既有列结构。“报名总览”为照片题目显示易读内容，例如“2 张照片”，并在相邻的照片链接列提供管理员可点击的链接。没有上传时显示“未上传”。

现有活动重新生成“报名总览”后也使用同一排法；旧报名没有照片资料时保持“未上传”，不会损坏旧数据。

## 安全与限制

- 参加者答案的 Drive 文件与文件夹始终保持私人，不设“知道链接的任何人”。
- 只有管理员明确附加到题目的说明图片才允许匿名读取；题目图片文件夹本身保持不公开。
- 只接受 JPEG、PNG、HEIC、HEIF；扩展名不能代替 MIME 检查。
- 默认每题最多 3 张、每张 5 MB；服务器另设每次报名总上传量上限，防止滥用和 Apps Script 请求过大。
- 文件内容不会写入日志、操作记录或 GitHub。
- 上传请求继续使用现有报名 API，不新增公开的任意文件写入接口。
- 管理员删除或取消报名不会自动删除照片；保留历史资料。未来如需资料保留期限，再独立设计清理策略。

## 错误与反馈

参加者会看到具体错误，而不是笼统的“提交失败”：

- 照片数量超过限制；
- 单张照片超过容量；
- 文件格式不支持；
- 上传中断，请重试；
- Drive 尚未配置，请联系管理员；
- 报名已截止或座位已被占用。

上传期间提交按钮禁用，避免重复报名。网络失败后保留表单普通答案和已选本地照片，让参加者可以直接重试。

## 代码范围

预计修改范围：

- `staff-apps-script/Admin.html` 与 `AdminScript.html`：管理员题型与设置；
- 管理员图片上传服务：题目说明图片的上传、替换、移除和公开显示 URL；
- `apps-script/Code.gs`、`RegistrationService.gs` 及必要的储存辅助模块：公开资料、服务器验证、Drive 写入和回滚；
- `public/js/registration-flow.js`、`domain.js`、`register-page.js`、`api.js` 与样式：选择、预览、验证、上传状态和提交载荷；
- `ReadableViews.gs`：报名总览的照片数量与管理员链接；
- `Repository.gs` 或系统设置定义：照片设置的规范化与安全默认值；
- 对应自动测试、Apps Script VM 测试、前端行为测试和生产组合测试；
- 部署用 source bundles 与 paste-ready 输出由既有生成流程更新，不手工复制过时代码。

## 测试与验收

必须先写会失败的测试，再实现以下行为：

- 管理员可保存照片题型及限制，非法设置被拒绝；
- 管理员可为任意题型上传、更换和移除一张题目说明图片；
- 匿名报名页可以显示题目说明图片，但不能列出或修改 Drive 文件；
- 报名页能选择、预览、移除照片并显示上传状态；
- 必填、数量、格式和大小在前端与后端均有相同结果；
- 合法照片进入正确的私人活动／报名文件夹；
- Sheet 保存元数据并在报名总览显示数量与链接；
- 任一步失败会回滚照片和报名资料；
- 公共活动资料和电子票不会泄露 Drive ID 或私人链接；
- 原有无照片报名、选座、电子票、找回票券和签到测试全部继续通过。

上线前需要在测试活动完成一次 iPhone 相册选择、一次现场拍照、一次超大文件拒绝、一次网络失败重试，以及一次管理员从 Sheet 打开照片的端到端验证。
